# 局域网剪贴板同步（lan-sync）

> 版本 0.2.5｜契约：[docs/api/lan-sync.md](../api/lan-sync.md)｜调研与决策：`dev/interface-drafts/`

## 这是什么

局域网内运行 VitryTool 的多台终端自动互联：**本机复制的内容自动广播**，其他终端的「收件箱」中按来源终端分组展示（每端最新 8 条），点击条目即可写回自己的剪贴板——不打断、不自动覆盖。

技术栈：libp2p 0.56（mDNS 发现 + TCP/QUIC 连接 + gossipsub 广播），纯局域网、无云端。

## 使用方式

- **收件箱页**（主窗口侧栏「收件箱」）：按终端分组查看收到的内容；**单击条目**写回剪贴板（同时进入本地剪贴板历史）；悬停条目出现「删除」；顶部「清空全部」。
- **设置页 → 局域网同步**：广播开关（默认开，本机复制即广播）、接收开关（默认开，入收件箱）、终端名（默认主机名）、在线终端数、本机 ID。
- 侧栏「收件箱」带**未读徽标**：在收件箱页之外收到新广播时计数，进入收件箱页清零。

## 行为要点

- **广播**：剪贴板历史捕捉到**新条目**（去重命中不算）且广播开关开启时自动发布；文本 / HTML / RTF / 文件路径随消息发送，**图片首版仅元数据**（名称/尺寸），字节传输见 TODO。
- **收件箱**：按来源节点分桶，每桶最新 **8 条**，全局最多 **8 个节点**（新节点挤掉「最久未活动」的整桶）；内容指纹去重（重复内容刷新置顶不新增）；本机自己的广播不入箱；收件箱跨重启保留。
- **回写**：写系统剪贴板 → 进入本地历史；因内容指纹命中「近期接收集合」，**不会**再广播回网络（防回环）。
- **防环**：近期接收指纹 LRU（100 条），拦截「回写 → 系统回环 → 再广播」。
- **上限**：广播单条 **1MiB**，超限静默跳过（仅日志）。

## 架构

```
features/clipboard_history ──(新条目 is_new)──▶ core/hooks ──▶ features/lan_sync（信封/收件箱/防环/开关）
                                                              │
                                              core/peer_node（身份持久化 + libp2p 节点，跨功能复用）
                                                              │
                                                        局域网（mDNS 发现 → 连接 → gossipsub 广播）
```

- **core/peer_node**：横切节点层（ed25519 身份持久化 + swarm 生命周期 + 通用 pubsub 通道），后续功能（文件传输、多设备会话）直接复用。
- **features/lan_sync**：业务层（信封协议、收件箱分桶、防环、开关、命令），不感知网络细节。
- 单实例（tauri-plugin-single-instance）保证一台机器一个终端。

## 已知限制（README 同步）

- **Windows 虚拟网卡可能使 mDNS 发现失败**（尤其 WSL 虚拟交换机 / Hyper-V Default Switch）：组播出口按路由 metric 选择，查询可能发进虚拟网段 → 本机发现不了别的终端（但能被发现）。已实测关闭 WSL 虚拟交换机后恢复；临时规避：以管理员 `route delete 224.0.0.0 mask 240.0.0.0 <虚拟网卡IP>`，或调高虚拟网卡接口 metric。
- 广播单条上限 1MiB，超限静默跳过；分片随图片字节传输（TODO）一起实现。
- 文件首版仅广播路径文本（跨机可能无法访问该路径）；文件字节传输见 TODO。
