# 功能文档指南

每个功能必须有一份**详细功能文档**：`docs/features/<feature>.md`（文件名与功能名、后端 mod 名一致）。

## 目的

功能文档回答「这个功能是什么、怎么用、边界在哪」，是 README 与代码之间的桥梁；接口细节在 `docs/api/<feature>.md` 契约文档中，二者互相引用、不重复。

## 编写时机

- 功能**签发**（从规划进入实现）时创建初版；
- 功能实现过程中随实现细节更新；
- 功能行为变化时同步更新。

## 文档结构（模板）

```markdown
# 功能名

- 状态：规划中 | 开发中 | 已完成
- 接口契约：[docs/api/<feature>.md](../api/<feature>.md)
- 后端 mod：src-tauri/src/features/<feature>/
- 前端目录：src/features/<feature>/

## 目标
<功能要达成的用户目标>

## 使用场景
<典型用例，含局域网的网络形态说明>

## 架构位置
<该功能在后端 mod / 前端目录中的结构，模块职责>

## 数据流
<关键路径的调用时序，从 UI 到后端再返回>

## 安全与边界
<访问控制、数据加密、局域网边界、失败处理>

## 测试要点
<测试覆盖重点；测试本身写在代码中>
```

## 检查清单

- [ ] 目标与使用场景明确
- [ ] 接口契约文档存在且最新
- [ ] 后端 mod 与前端目录名一致
- [ ] 安全边界（局域网场景）有说明
- [ ] 测试要点已记录，代码中有对应测试
- [ ] 版本号与 CHANGELOG 已按 [versioning](../versioning.md) 更新
